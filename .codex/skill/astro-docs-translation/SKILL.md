# astro-docs 多语言翻译与复核

以简体中文原文为内容基准，以目标语言普通读者能自然理解为完成标准。沿用本仓库已完成的多轮翻译流程；按本次任务选择全量翻译、增量同步或专项复核，不为小范围修订重写无关页面。

本文中的路径均相对于 astro-docs 根目录，资源链接相对于本 skill。当前用户明确提出的新要求优先于这里记录的既有约定。

## 范围与固定约定

- 目标语言由本次用户要求、当前站点配置和语言目录共同确定，不使用固定语言名单。已有语言和未来新增语言复用同一流程；每种语言直接对照中文，不以另一份外语译稿作为唯一中间稿。文档目录代码、站点 `lang` 与 iztro 语言代码分别确认，不能假定三者格式相同。
- **中文删除须同步所有语言。** 删除简体中文的正文、段落、表格、页面、导航、侧栏或首页内容时，同步删除当前站点所有其他语言中的对应内容，包括繁体中文；不能只处理参与外语自动检查的语言。按语义和链接目标定位对应项，并清理直接关联的入口、站内链接及失效语义记录，避免遗留译文或死链；保留与本次删除无关的内容。
- 默认排除 `learn/ancientBook*.md`，不补译或改写古文章节。外语导航继续排除这些入口；正文已有的古籍链接可指向中文原文。
- 非古文章节中引用的古籍原文，按 `scripts/classical-quote-policy.json` 保留繁体中文原文；周围的现代说明仍需翻译。不要因章节含古文引文而跳过整页，也不要把引文改写为解释。
- 品牌名 **紫微研习社** 在所有语言中保持这五个简体中文字不变，包括繁体中文页面。站点标题、首页名称及品牌引用均不改为译名、拼音或“紫微研習社”。
- API 标识符、属性、类型、枚举原值、参数字符串、可执行代码示例、数字索引、版本号、共享图片和组件路径保持原有含义及有效性。中文行内代码可能只是强调，需按上下文判断，不能一概保留或一概翻译。
- 术语优先依据 iztro 对应语言词表和本仓库已核定译法；尚无对应词表时，按中文含义建立并记录该语言的显示译法，不伪造库支持或修改现有 API 值。正文、标题、表格、描述、导航使用同一套概念名称。说明性表达可以自然改写，不能据此修改 API 返回值或输入值。
- 为每种目标语言记录专业术语显示及括注规则。新增语言默认在正文专业术语后附繁体中文原名；若该语言自然使用相同汉字术语，则使用本语言术语，记录不重复括注的规则。现有语言沿用已核定约定，例如日语不额外附中文原名。普通表达不因用了反引号而添加中文术语注解。
- **格局章节 `learn/pattern.md` 的外语表格不添加中文括注**。保留译名、排列、干支、星曜、四化和数值；目标语言原有汉字术语不是待删除的中文注解。这个例外不扩大到正文、标题或其他表格。
- 导航和首页使用简洁的本语言文案，不机械堆叠正文的中文括注；品牌名仍使用中文。首页浏览器标题中的品牌只出现一次。

## 执行流程

新增目标语言时，先按 [新增语言接入指南](references/adding-languages.md) 确定语言标识、术语与括注规则、站点入口及检查覆盖，再复用以下翻译和复核流程。不要把示例语言的语法、检测规则或库支持情况直接复制给新语言。

1. **确认变更范围。** 从任务和站点配置确定本次目标语言集合，识别是否为新增语言；查看仓库现状和检查基线，保留已有修改。按 [增量同步与范围记录](references/review-guide.md#增量同步与范围记录) 列出源文变化、目标页面和受影响入口，区分本次问题与既有问题；不要使用上次任务的固定页数作为覆盖清单。
2. **建立翻译依据。** 阅读 `scripts/translation-terms.json` 及任务相关语义记录。需要核查库的实际值时，查看可访问的 iztro 源码 `src/i18n/locales/<locale>/`；源码可能在相邻仓库，先确认位置与版本，不能假设固定绝对路径。词表与源码不一致时查明原因。
3. **翻译或同步内容。** 按页面和语义单元处理，保留 Markdown、HTML/Vue、表格结构和原始中文锚点。迁移站内链接至对应语言目录，保留外链、共享资源及允许的中文古籍链接。机器翻译只可作为草稿，不能以“没有中文残留”作为完成标准。
4. **完成分轮复核。** 按 [多轮复核指南](references/review-guide.md) 依次检查术语与数据、普通读者理解、标题/表格/页面描述、导航/侧栏/首页。专项任务只执行相关轮次，并检查受影响的交叉引用。
5. **验证并修复。** 按 [验证与交付指南](references/validation.md) 执行现有检查，核对检查覆盖范围，再构建和检查相关输出。先判断失败来自译文、中文源变动还是已核定词表过时，不能为通过而放宽校验。记录实际检查的语言及页面范围；定点检查、部分记录比对和构建成功均不能代替完整的语义复核。
6. **最终语义验收。** 自动验证后，按 [最终验收：四项专项检查](references/review-guide.md#最终验收四项专项检查) 对本次范围再检查一遍：专业术语未被译成普通词义、强调词与整句衔接、表达符合目标语言地区习惯、接口方法和参数保持实际标识符。必须结合中文、目标整句和相邻上下文判断；修订后重跑受影响验证。
7. **核对最终差异。** 确认古文章节和范围外内容未被改动，术语与页面入口一致，最终保存文件就是验证过的修订稿。交付说明具体修订范围、验证结果及仍未解决的问题；仅在确实完成相应检查时报告通过。

## 如何维护既有记录

使用仓库现有脚本和语义记录，不另建一套平行词库。各记录用途及更新边界见验证指南。新增或修改已核定译法时，先对照中文与上下文核实，再同步相应记录；单页特殊语义优先记录文件范围，避免全局替换。

若本次只编辑翻译维护文档或 skill，无需因此重跑整个站点构建；检查 skill 结构、相对引用和规则一致性即可。实际译文或站点配置变更则按验证指南处理。
