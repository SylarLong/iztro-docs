# 验证与交付指南

## 先明确覆盖范围

三个检查入口共用 `scripts/translation-context.mjs`，从 VitePress 解析后的站点配置发现所有非根语言；未将语言的 `themeConfig.translationChecks` 设为 `false` 时默认纳入。繁体中文目前显式沿用独立繁简维护流程，配置为不参加外语翻译检查。`CHECK_LOCALES` 可选取已启用语言的子集，三个入口均使用相同的选择；空筛选、未知语言或被排除语言会报错。新增语言无需修改脚本名单，但必须补齐页面、词表和所需语义记录；检查会报告缺失的语言数据，不以默认语言的数据代替。具体接入见 [新增语言接入指南](adding-languages.md)。

从当前目录树和本次中文变更建立页面清单，排除 `ancientBook*.md`。确认每个目标语言有对应页面，且验证脚本包含它。现有脚本包含入口页、指定 AI 页面及 `posts`/`learn` 下非古文页面；新增其他目录或 AI 页面时，应确认是否需要扩展页面发现范围。不能把“检查通过但新页面没有被检查”当作完成。

`translation-terms.json` 的 `glossPolicy` 指定正文括注策略；`localeRules` 记录 `nativeHan`（是否使用本语言汉字，默认 `false`）及 `workSchedulePattern`（工作制度说明的本语言匹配表达式）。这些键用于语言规则，不用于选择检查哪些语言。表格校验只比对已核定的目标值，不能把校验数量理解成所有单元格都已人工核查。

本次建立的记录可作为依据，未来应随源文和库版本维护；不要把某次运行的页数、表格数、代码数量或 iztro 版本号固定为完成门槛。

## 现有脚本与记录

以下路径相对于仓库根目录。根据本次改动阅读有关条目，不必每次把所有词库全文载入。

| 文件 | 用途与更新边界 |
| --- | --- |
| `scripts/translation-context.mjs` | 从站点配置读取语言，统一筛选、古文排除、页面完整性和语言数据检查 |
| `scripts/verify-locales.mjs` | 验证页面结构、标题层级、源锚点、代码示例、HTML/Vue、链接及部分韩语宫位语义 |
| `scripts/verify-product-tables.mjs` | 单独检查所有配置语言（含繁体中文）的快速开始“产品”表格与简体中文原表完全一致；不受外语翻译检查筛选影响 |
| `scripts/verify-translations.mjs` | 检查术语、行内代码值、表格、算术、格式、中文括注及格局表格不含附加中文注解 |
| `scripts/verify-semantic-locales.mjs` | 比对已复核表格含义，检查语义记录、拼音残留和特定文化表达 |
| `scripts/translation-terms.json` | 术语、普通词、显示值、上下文短语及 API 词表依据；不能把改善普通说明文案当成改动 API 值的理由 |
| `scripts/table-semantic-review.json` | 对照中文核定的表格译法；用 `file` 限定特殊语境，避免相同短语在无关页面被全局覆盖 |
| `scripts/prose-alias-review.json` | 普通说明里的旧音译、英文残留与推荐本地化表达 |
| `scripts/emphasis-semantic-review.json` | 反引号强调短语的语义与是否需要术语括注 |
| `scripts/classical-quote-policy.json` | 非古文章节中仍须逐字保留的繁体古文引文、行内短句及字面内容 |

更新语义记录之前，先对照中文源单元、目标上下文与库词表。区分真正的译文错误、中文源文变更和过时的核定值；修改后运行相关检查。保留对代码、链接、结构和其他页面的保护，不删除断言或扩大例外来迁就错误译文。确需新增例外时，限定具体页面、区域和原因，同时维持针对新约定的检查。

格局表格的例外适用于所有外语：术语仍检查本语言显示值，不添加中文括注，同时保留目标语言本来使用的汉字。新增语言时让验证器按该语言的显示与括注规则区分“附加中文注解”和“合法的本语言文字”，不能固定以某一种语言代码作为唯一例外。不能通过全局取消中文检测来实现。

## 语言数据与核定值

语言自动纳入检查，与语言数据完整是两件事。当前检查器会拒绝缺失的主要词表和规则，但不会证明每个词条或每个单元格都已有人工核定值。按本次源文涉及的概念与单元逐项核对，不能只检查字典对象非空。

| 数据位置 | 接入或修订时确认 |
| --- | --- |
| `translation-terms.json` 的 `terms[locale]`、`ordinary[locale]`、`display[locale]` | 三类对象非空只是入口条件；仍需覆盖实际使用的专业术语、普通表达和显示概念，保持代码原值与显示译名的区分 |
| `ordinaryVariants[locale][source]` | 普通短语因语境需要变格或调整大小写时，可登记核对后的自然变体；不通过改写专业术语或 API 字面值来解决语法问题 |
| `glossPolicy[locale]` | 显式使用 `traditional-Chinese` 或 `none`；不根据目录名、文字系统或 `nativeHan` 自动推断 |
| `localeRules[locale]` | `nativeHan` 决定允许本语言汉字；`workSchedulePattern` 是具有实际区分能力的本语言表达式 |
| `contextualPhrases[].values[locale]` | 当前上下文短语记录须有目标语言值，保留对应的 `file`、源文前缀与普通含义 |
| `prose-alias-review.json` 的 `rules[].targets[locale]`、`emphasis-semantic-review.json` 的 `expressions[].targets[locale]` | 当前记录须补齐目标值，并核对本语言适用的旧译名、术语和普通表达 |
| `table-semantic-review.json` 的 `cells[].targets[locale]` | 当前自动语义比对使用 `decision: "corrected"` 的记录；逐语言先取文件专用值，缺少时回退到通用值。两者都没有时该单元格不会被自动语义比对，需人工复核并补充本次适用的核定值 |

表格数据预检只要求该语言至少有一条已核定记录，不能保证整页覆盖；`retained` 记录也不等同于已进入自动语义断言。检查输出的核定数量表示实际进行了多少次比对，不表示全部译文质量已获证明。新增语言或修改表格时，应核对源单元、目标语言和有效核定值的对应关系，检查文件专用记录是否覆盖了本语言的实际语境。

## 必要验证

在 astro-docs 根目录执行：

```sh
npm run docs:check-locales
```

修改语言接入配置、校验脚本或其语言规则时，运行 `npm run docs:test-locales` 验证语言发现、缺页/缺少语言数据、筛选一致性、语义回归和古文排除。普通文案修订无需因此反复运行这套脚本回归测试。

`docs:check-locales` 串联结构、翻译和语义检查。做全量验收前确认当前环境没有遗留的 `CHECK_LOCALES` 筛选，并核对输出语言集合与站点启用集合一致；定点检查只说明所选语言通过。`npm test` 当前是占位脚本，不作为翻译验收命令。只做定点排错时可用 `docs:check-translations`，但最后的翻译验收仍需完整 `docs:check-locales`。

修改译文或站点配置后执行：

```sh
npm run docs:build
```

构建前检查 `.vitepress/config.mts` 的 `outDir`：当前输出指向相邻 astro 仓库的 `docs`。若该输出会覆盖正在使用的文件或超出本次可写范围，在隔离临时副本中验证，复用可用的依赖；不要为了文案校验向真实输出目录写入未经检查的生成文件。保存回目标仓库前检查源文件未被并发修改，保存后确认内容与验证稿一致。构建成功不是发布授权。

全量检查若因范围外的既有问题失败，记录失败与基线的关系；必要时对本次语言做定点检查，但须明确“定点通过、全量仍失败”，不扩大翻译范围或放宽检查来掩盖问题。

对实际失败进行修复，并在修订后重新运行受影响检查。既有体积警告与构建失败应区分，不能报告未执行或失败的构建为通过。文案验证通过后，不需要为同一份未变化稿件反复扩大测试范围。

## 自动检查覆盖不到的部分

所有自动检查通过后，仍需完成读者复核。现有正文检查会跳过 frontmatter 的大部分语言语义，菜单短语也没有因命令通过就自动与正文一致。`nativeHan: true` 只允许本语言汉字，不能区分每一处汉字是自然译文还是中文残留；格局表格的附加括注、语序和指代也需按复核指南人工检查。

首页和导航改动还应核对：

- 从 VitePress 解析后的配置或构建输出确认新文案实际生效，不能只看未使用的词表。
- 比较修订前后菜单层级、项目顺序和链接目标；检查本语言站内链接、按钮目标及古文入口排除仍正确。
- 解析首页 frontmatter 或检查生成页面，确认标题、名称、卡片、按钮和页面描述完整，HTML/SVG 与链接未损坏。
- 检查所有语言的品牌名；繁体中文中只有固定品牌使用“紫微研习社”，不因此把其他繁体正文改为简体。
- 检查最终浏览器标题没有重复品牌；导航文案长度增加或布局相关变更时，再做相应视口的视觉检查。

检查对象应包括渲染结果与实际含义，不能只搜索“旧词已经消失”。例如数字、五行、时段、宫位含义仍需与中文逐项核对；目标语言原有汉字、中文古文、代码中的语言输入样例，也不能按“外文中存在中文”一律判错。

## 最终差异与交付

确认只有本次授权范围的源文件和必要语义记录变化。古文章节保持原状，原有用户修改被保留；没有临时提取文件、占位符、草稿标记、生成站点或依赖目录误入修订。

交付时用中文简要说明改了哪些语言与区域、解决的主要问题，以及实际运行的检查结果。存在未解决的源文歧义、不可用构建环境或未覆盖页面时说明限制，不笼统宣称所有目标语言已全部复核完成。无需自动提交、发布或创建 PR。
