# 新增语言接入指南

本 skill 不限定语言数量或语言名单。为任意新语言完成以下接入后，直接复用主流程及多轮复核指南；只更新已有语言时无需重复建立整套接入资料。

## 1. 确认语言标识与范围

从用户任务确定目标语言与地区变体。查看现有目录、`.vitepress/config.mts`、`.vitepress/locales.mjs`，确认文档目录代码、VitePress locale key、页面 `lang` 和界面语言匹配方式。目录可能用下划线，网页语言标识可能用连字符；按现有约定建立映射，不照搬示例字符串。

以中文非古文页面生成覆盖清单，确认新增语言需要的首页、介绍、开发文档、知识章节和 AI 等页面。保留中文锚点，站内文档链接指向该语言；古文章节及其导航入口继续按主流程排除。用户只要求部分页面译稿时，不自动扩展任务，也不把它当作已完成整站接入。当前启用检查的语言必须具备检查清单中的全部页面；部分译稿先保持未启用草稿状态，在临时预览配置中做对应检查，并明确剩余范围。不得用中文原文或其他语言复制填满缺页，也不得关闭检查来冒充完成接入。

## 2. 建立目标语言规则与词汇

沿用仓库现有词表结构，在相应记录中新增目标语言条目，不复制另一语言的译法来填空。记录目标语言的核心概念译名、术语显示规则、繁体中文括注规则、普通表达和需要保留的字面值。注明显示译法依据和库的实际支持状态；语义相同的别名可以共享概念，不同语境的普通含义不能被术语译名覆盖。

优先查 iztro 是否已提供该语言的词表，并核对版本。**文档支持一种语言，不等于库已经支持这种语言的输入、输出或 `Language` 参数。** 若库不支持新语言，可翻译说明文案并建立术语显示译法，但示例仍使用真实可用的参数和返回值，不臆造语言代码、枚举值或 API 支持，也不将示例的外语实际输出误判为未翻译。

目标语言缺少成熟术语时，按中文含义选择清楚、稳定的表达并记录依据；既有语言示例只作概念参照，不能作为唯一中间译稿。遇到确实影响含义且无法从原文或上下文消解的歧义，标明问题并处理其他可确定内容。

正文括注使用主流程的默认约定，并记录该语言是否自然使用汉字术语等例外。普通表达、首页短按钮和导航不机械附加中文注解；所有外语格局表格均不添加中文括注。品牌名仍是“紫微研习社”。

## 3. 接入站点与界面

为目标语言添加或补齐站点配置、语言自称、网页语言标识、导航/侧栏词表、首页、文档页脚、页内导航和相关界面提示。检查当前组件如何选取语言，必要时补充对应文案，避免新语言静默退回默认语言。

维持中文菜单的层级、顺序和功能对应。新增的是文档语言时，不修改首页“库支持哪些输入输出语言”的真实说明来冒充库功能扩展。根据该语言实际需要检查字体、断词、文案长度、日期/数词和书写方向；使用从右向左书写的语言时核对方向与代码、数字的混排表现，不自动扩大为全站样式重构。

## 4. 让检查实际覆盖新语言

三个验证入口已通过 `translation-context.mjs` 从站点配置自动发现语言。新增语言在站点配置登记后默认进入检查，不需要逐脚本添加语言代码；将语言的 `themeConfig.translationChecks` 设为 `false` 仅用于明确采用其他维护流程的语言，不应作为绕过新语言检查的手段。检查词表索引、语言特定规则和缺省行为。让目标语言进入结构、代码、链接、术语、表格和语义检查，并确认所需语义记录有目标语言的核定值。缺少记录被跳过不算通过验证。

在 `translation-terms.json` 中补齐该语言的 `terms`、`ordinary`、`display`、`glossPolicy` 和适用的上下文短语，并在 `localeRules` 中登记本语言的 `workSchedulePattern`；若自然使用汉字，设置 `nativeHan: true`。补齐拼音/旧译名记录、强调短语记录和已核定表格译法的目标值，运行三个入口确认新语言名称出现在结果中。具体字段及覆盖边界见 [语言数据与核定值](validation.md#语言数据与核定值)，不能只添加一个表格核定值便认为整页语义都已受检。`CHECK_LOCALES` 只用于从已启用语言中选择子集，不用于注册语言。

`nativeHan` 与 `glossPolicy` 是独立规则：允许目标语言原有汉字不等于已翻译正确，也不会自动关闭正文括注；需要显式设置 `glossPolicy`。`workSchedulePattern` 使用当前检查器的 `iu` 标志，应验证它确实匹配该语言对源文工作安排的解释，不能用 `.*` 等无条件表达式代替核查。

中文残留、汉字术语、拼音/英语残留、工作制度等文化表达及术语括注检查，应按目标语言特性适配，不直接复制另一语言的正则表达式。保留原有语言的检查，不能以新语言暂时不适配为由全局关掉断言。明确记录仍需人工核对的部分。

## 5. 复用完整翻译流程并验收

完成初译，依次进行术语和表格复核、普通读者通读、标题与元数据复核、导航与首页复核，再按 [验证与交付指南](validation.md) 检查和构建。验收证据要能对应到本次目标语言，而不仅是既有语言。

确认实际生成了目标语言页面，语言入口能到达正确首页，站内链接仍在目标语言，真实渲染文案和品牌正确，古文与 API 示例按约定保留。交付说明本次加入或处理的语言、覆盖范围，以及库本身是否支持该语言，避免把文档本地化范围与库能力混为一谈。
