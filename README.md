# iztro-docs
document of iztro

## 页面 SEO 维护

公开页面（包括古籍页）须在 frontmatter 中填写与正文对应的本语言 `title` 和 `description`，避免复制其他页面的摘要或堆叠关键词。正文 API 标识符和原有锚点保持不变。古籍页只维护元数据，不因此改写古籍正文。

正式域名为 `https://iztro.com`，由 `.vitepress/seo.mjs` 统一生成 canonical、多语言 hreflang、Open Graph、Twitter 卡片和 JSON-LD；页面 URL 沿用现有 `.html` 规则，首页使用目录 URL。新增语言后仅为实际存在的译文生成语言链接。旧的 `/en_US.html` 页面保留访问能力，标记为不收录，并指向 `/en_US/`；README、AGENTS 和 skill 文件不生成公开页面。

`public/robots.txt`、`CNAME` 与 sitemap 须保持同一域名；`.vitepress/public/robots.txt` 是同步副本。构建完成后会将 `static/` 复制到输出目录，确保分享图片、图标和 Web Manifest 可访问。

修改后运行 `npm run docs:test-seo`、翻译检查和构建，并核对生成 HTML 的标题、摘要、canonical 与 hreflang，以及 sitemap 和资源路径。默认构建目录位于相邻仓库；需要隔离验证时使用临时副本，避免覆盖正式输出。


## 多语言文档维护

简体中文是结构与内容的基准。英语（`en_US`）、韩语（`ko_KR`）、日语（`ja_JP`）和越南语（`vi_VN`）覆盖与中文一致的非古文页面；`learn/ancientBook*.md` 暂不翻译，正文中的古籍链接指向中文原文。

本轮补全以机器翻译草稿为基础，紫微斗数术语优先采用 iztro 的多语言词表。发布前建议由对应语言的读者校对术语、语气和长篇解释。代码示例、API 名称、参数和原始中文标题锚点保持不变。

新增或更新中文页面时，请同步站点配置中启用翻译检查的目标语言目录。翻译后的标题使用 `{#中文原始锚点}` 保留章节跳转，站内文档链接指向对应语言目录，共享图片和组件路径保持不变。导航由 `.vitepress/locales.mjs` 根据中文导航生成；新导航标题需同步更新各目标语言的词表。

三个翻译校验脚本统一从 VitePress 站点配置读取目标语言，新语言默认自动纳入；不再维护脚本中的语言名单。在语言配置中设置 `themeConfig.translationChecks: false` 表示使用独立维护流程，繁体中文目前沿用这一方式。缺少译文页面、词表或必要语义规则时会明确报错。`CHECK_LOCALES` 可用于筛选已启用语言，三个入口保持一致。语言的括注、汉字使用和工作制度表达规则保存在 `scripts/translation-terms.json`，不用于决定检查范围。

验证结构与链接：

```sh
npm run docs:check-locales
```

测试语言自动发现、缺失数据与古文排除：

```sh
npm run docs:test-locales
```

构建站点：

```sh
npm run docs:build
```

### 翻译核查约定

- 标准 iztro 术语使用库中对应语言的名称，英语、韩语和越南语的说明文字后附繁体中文原名，例如 `advisor`（天機）；日语使用日语术语，不添加中文括注。外语格局章节的表格不添加中文括注，目标语言原有汉字术语保留。实际 API 代码、参数表达式和多语言输入样例保留可执行的原值，中文括注不写入参数字符串。
- 普通表达按目标语言翻译，不因使用行内代码就保留中文。例如 `加6` → `+6`，`加减4` → `±4`，`外部环境` → `environment`。
- 表格逐单元格核对名称、顺序、阴阳、五行、数值和时间范围；共享索引及接口标识符保持不变。
- 章节标题和链接文字使用目标语言；`Xingyao`、`Zayao`、`Liu Yao`、`An Xing Jue` 等拼音不作为译文。括注中的术语保留繁体中文，地支「丑」与「斗數」的「斗」按术语本字保留。
- 韩语术语解释按中文语义校对：后天八卦、天门、地门、宫位方位等不能只检查拼音是否消失。补充词汇与拼音残留记录在词表中；`docs:check-locales` 对天门、地门及相关宫位另作语义校验。
- `scripts/translation-terms.json` 记录本轮对照的 iztro 术语及通用词汇。语言定义更新时应同步词表和类型定义对照。
- `npm run docs:check-locales` 同时检查结构和翻译约定，包括术语括注、普通短语、算术记号、表格空值及加粗/斜体是否实际解析成功。

- 反引号可能只是强调。普通用语和游戏比喻按上下文翻译，不套用星曜术语，也不加中文术语括注。
- 对中文网络用语采用目标语言读者能理解的同义表达。例如 996/007 写明每周六、七天长时间工作，PUA 按本篇语境表达为心理或情感操控；“韭菜”“创建小号”“软饭王”等不能照字面翻译。
- `scripts/table-semantic-review.json` 保存按中文核查的表格译法；语义检查对照已核定的描述，并检查工作时间缩写和情感操控的表达。修改中文时需要重新核对对应语义，不能只改检查结果。
- 打赏组件根据当前文档语言显示提示、收款码说明和 PayPal 入口。
